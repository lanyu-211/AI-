# Pinmark 高保真原型打点备注技能规范 (pinmark-annotation)

本规范专为高保真 HTML 原型项目的 **Pinmark 批注组件** 制定，用于指导 AI 助手后续在开发新页面、重构界面或进行需求整理时，能够以最高效、最准确、去技术化、对多方角色友好的方式进行原子需求备注的打点与存储。

---

## ⚖️ 1. 依码据实与代码审查准则 (Grounding Rule - 严禁脑补)

为了防止需求备注与原型系统的真实代码行为脱节，AI 在生成图钉备注前，必须严格遵守“依码据实”的铁律：
- **前置代码审查**：在生成任何图钉的备注内容前，AI **必须**首先使用文件读取工具物理查阅目标页面在前端代码中的真实实现（如相关的 JS 方法体、Vue 的生命周期或事件处理器）。
- **禁止凭空捏造**：备注中描述的“判定条件”、“系统动作”与“UI反馈”，必须在当前原型代码中有**真实的逻辑支撑**。
- **原型局限性明确标注 (TODO 规则)**：
  - 如果原型中未实现某项业务规则（但在您的 PRD 文档中有所设计），AI **严禁**假装该规则已在原型中生效。
  - 必须以 `[TODO]` 前缀清晰注明原型阶段的局限性。
  - *示例*：`[TODO] 目前原型仅作静态演示，真实开发实现时需在点击提交时追加防重复点击拦截。`

## 🎯 2. 强锚点绑定与防遮挡定位规范

在页面上进行打点时，必须严格遵守以下定位逻辑，防止图钉错位或遮挡正常页面内容：

### 1.1 精准定位“叶子节点”与强锚点注入
- **严禁**将图钉挂载在大范围的容器 div、section 或灰色背景上。
- **锚点前置原则**：打点前，必须先检查宿主元素是否含有 `data-pinmark` 属性。
  - 若无，必须先修改对应的 Vue/HTML 视图文件，在目标 DOM 元素上注入全局唯一且语义化的属性：`data-pinmark="unique-element-id"`。
  - 之后，图钉的 `targetSelector` 必须设定为 `[data-pinmark="unique-element-id"]`。
- **Element Plus 动态 ID 防护律**：
  - 如果未通过 `data-pinmark` 锚定，而需要使用 fallback 选择器定位时，**严禁包含任何以 `el-id-` 开头的 ID** (例如 `el-id-5210-4`，这是 Element Plus 运行时动态生成的，每次重新挂载都会变动导致定位失效)。
  - 应当剔除此类动态 ID，改用结构树选择器（如 `nth-of-type`）或带有语义的属性（如 `name`、`aria-label` 等）进行稳定定位。

### 1.2 右上角贴边角标定位 (percentX: 1.0, percentY: 0.0)
- **严禁**使用默认的中心定位 `(percentX: 0.5, percentY: 0.5)`，因为这会完全挡住按钮上的文字、输入框的焦点以及列表单元格内的数字。
- **右上角定位律**：图钉的相对偏移量必须设为右上角贴边，即：
  ```json
  "percentX": 1.0,
  "percentY": 0.0
  ```
  这样图钉会以“右上角红色/蓝色角标”的精致形态悬浮在元素边缘，既醒目又完全释放了宿主元素中心的核心内容，不干扰用户的原型演示和正常点击。

## 📝 2. “3D-6P” 就地需求备注标准框架

每个功能图钉的备注，严禁书写冗长的业务“小作文”，必须结构化地拆解为 **【输入触发】、【业务逻辑】、【状态决策表】** 3 个维度共 6 个核心项：

### 2.1 需求备注 Markdown 标准模板

```markdown
### 📌 [组件名称] · 需求规格

**1. 输入与触发 (Trigger & Input)**
- **触发行为**：[用户何时交互？如：点击按钮 / 输入框失去焦点 / 键盘输入]
- **数据约束**：[输入什么？如：限制正整数 / 必填项校验 / 默认自动填充的值]

**2. 核心逻辑与状态联动 (Logic & State)**
- **业务规则**：[系统后台如何计算？如：逻辑步骤 / 状态变更的中文业务公式]
- **影响范围**：[联动什么？如：更新当前商品库存数 / 记录日志流水历史]

**3. 界面反馈与异常分支决策矩阵 (Feedback & Edge Table)**

| 触发场景 (Scenario) | 判定条件 (Condition) | 系统处理动作 (Action) | 用户界面反馈 (UI Feedback) |
| :--- | :--- | :--- | :--- |
| **正常情况...** | 条件符合... | 处理业务数据状态... | 成功 Toast 提示并关闭弹窗/跳转... |
| **异常情况 1...** | 如：备注为空... | 执行缺省容错逻辑... | 正常保存并提示... |
| **异常情况 2...** | 如：数据溢出... | 拦截/警示... | 错误提示/红色高亮... |
```

### 2.2 简单/静态组件的“3D-6P 降维轻量化”规范

对于无复杂数据校验、无异常分支流程的简单展示型卡片、列表或只读文本等组件，强制套用决策矩阵会导致文档冗余。此时应采取以下“降维/轻量化”处理原则：

- **核心逻辑转换**：将“业务规则”转换为更贴近系统的隐含业务属性（如：**数据的排序规则、不同用户角色的权限可见性边界**）。
- **决策矩阵裁剪**：将第三维度的“异常决策表”替换为**【界面反馈与用户体验规范 (UX Standards)】**，重点约定 Hover 状态动效反馈、异步加载时的**骨架屏（Skeleton Screen）**占位规范，以及无匹配数据时的**缺省占位（Empty State）**要求。

#### 3.2.1 需求备注 Markdown 轻量化模板
```markdown
### 📌 [组件名称] · 需求规格 (轻量版)

**1. 输入与触发 (Trigger & Input)**
- **触发行为**：[用户何时交互？如：左键点击卡片区域 / 点击详情文字链接]

**2. 核心逻辑与权限边界 (Logic & Role)**
- **权限规则**：[什么角色可见/可点？如：仅系统管理员可见新增按钮，普通运营仅可只读查看]
- **排序规则**：[列表数据按什么顺序排列？如：默认按最后修改时间倒序排列]

**3. 界面反馈与体验规范 (UX Standards)**
- **交互动效**：[Hover 或点击有什么反馈？如：鼠标移入卡片整体上浮并加深投影]
- **首屏加载**：[网络异步拉取数据期间的占位体验？如：卡片网格统一使用骨架屏占位]
- **缺省说明**：[空数据时如何展示？如：搜索无结果时隐藏列表，展示“未找到匹配结果”提示插图]
```

## 🚫 3. “去技术化与业务解耦” 写作原则

由于高保真前端页面仅仅是 **“原型界面”**，真实的系统界面与后台服务未来会由开发人员重新实现。需求备注的文字描述必须彻底实现 **“业务层” 与 “技术层” 的解耦**，保持技术的“框架无关性”。

### 3.1 严格禁止出现的参数与名词
- ❌ **严禁**在备注文本中出现任何前端私有变量、Element Plus 特有类名、数据绑定语法及浏览器底层存储等技术名词。
- ❌ **示例**：`el-input-number`、`route.query.filter`、`sessionStorage`、`v-model`、`text-red-500` 等。

### 3.2 技术名词 ➔ 中文业务概念转换对照表

| ❌ 严禁出现的技术名词 |  必须替换的中文业务/交互概念 |
| :--- | :--- |
| `route.query.filter === 'warning'` | 首页看板“库存预警”卡片穿透跳转过来时 |
| `sessionStorage` / `localStorage` | 系统日志历史 / 全局缓存记录 |
| `el-input-number` / `el-input` | 数字输入框 / 文本输入框 / 条码输入框 |
| `Dialog` / `Drawer` | 弹出录入对话框 / 侧边抽屉面板 |
| `text-red-500 font-bold` | 文字高亮变红并加粗 |
| `NewStock` / `Difference` | 实盘总数 / 盘点差额 |
| `ratio` | 换算率 |
| `YYYYMMDD` | 年月日八位（如 20260801） |

## 💾 4. 数据落盘存储规范

所有的打点数据统一存储在项目静态资源根目录下的 `.pinmarks.json` 文件中，单条 pin 数据的 JSON 结构必须严格符合以下定义：

```json
{
  "id": "pin_unique_timestamp_or_name",
  "x": 0,
  "y": 0,
  "pageId": "/your-route-path",
  "text": "经过 3D-6P 框架重构并完全去技术化的 Markdown 备注文本",
  "targetSelector": "[data-pinmark=\"your-semantic-anchor\"]",
  "percentX": 1.0,
  "percentY": 0.0
}
```
- `pageId`：当前页面的路由路径，例如商品管理为 `/products`。
- `targetSelector`：强锚点选择器，格式必须为 `[data-pinmark="your-semantic-anchor"]`。
